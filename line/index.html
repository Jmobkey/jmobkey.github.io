Most of the design work in an AI system is deciding which parts can be probabilistic and which have to stay deterministic. List the steps in a workflow and answer five questions about each. Every step comes back with a view on whether a rule, a person or the model should make the final decision.

Workflow

One card per step, in order. Be specific about what the step actually decides. The sample is a generic warranty claim process.

The four outcomes

From most deterministic to least.

Rules only Plain code or a lookup does the job. A model would only add cost and variance.

Model reads, rules decide The model extracts, disambiguates or proposes. A deterministic check makes the call, so a near-match never gets through on the model's say-so.

Model drafts, person decides There is no checkable right answer, so a person stays accountable for the decision and the model saves them time.

Model acts, sampled A mistake is cheap. The model can act alone, with logging and regular sampling to catch drift.

What's missing

Five questions can't describe a real step, and the answers are yours, so this is only as honest as you are. Treat each call as a prompt. If it says rules and you disagree, find out why. The disagreement is usually a missing question.

Choices worth knowing about. Whenever rules fully cover a step the answer is rules, even where a model could do it, because predictable and cheap beats clever. A wrong answer that costs little always lets the model act alone, and one that costs a lot never does. Between those, whether the right answer can be checked decides whether a rule or a person makes the final call.

Not modelled: latency, volume, regulation, and what it costs to build the check itself. The sample workflow is generic and isn't taken from any employer.

The model can read almost anything. Whether it should also decide is a separate question, and the one that tends to go unasked.
